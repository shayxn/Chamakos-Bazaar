NO CASH ON DELIVERY FOR GIFT CARDS

A gift card must be successfully PAID FOR before its balance is created/activated.

Mixed Carts

Handle this properly.

If the cart contains:

Physical Product + Gift Card

then normal shipping options/address are still required for the PHYSICAL products.

However, the gift card itself must:

* Have no shipping charge
* Not affect package weight/delivery
* Not require physical fulfillment
* Be delivered digitally after successful payment

COD should not be offered for a mixed cart containing a gift card unless the payment architecture can securely prevent the gift-card value from becoming usable before confirmed payment. Prefer requiring online payment for any cart containing a gift card.

Security

Gift-card value is REAL monetary value, so treat this system as sensitive.

The SERVER must control:

* Gift card creation
* Balance
* Ownership
* Claims
* Redemption
* Remaining balance
* Payment verification

Customers must NEVER be able to edit their balance from the frontend.

Prevent:

* Guessing gift codes
* Guessing gift links
* Double claiming
* Double spending
* Spending more than the balance
* Creating gift cards without payment
* Reusing spent value
* Claiming someone else’s already-claimed card

Use atomic database operations for redemption so two simultaneous checkouts cannot spend the same balance twice.
